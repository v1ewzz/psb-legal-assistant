## 1. Принципы

1. **Одно ядро — два входа.** SSE-эндпоинт вызывает тот же
   `pipeline.answer_one(question, ctx, deadline)`, что и `solution.py`. Никакой
   отдельной «веб-логики» ответа.
2. **Фронт ничего не додумывает.** Все поля, которые видит жюри (статус,
   confidence, редакция, результаты проверки цитат), приходят с бэкенда.
   Мок-режим отдаёт ровно тот же JSON.
3. **Данные — не разметка.** В ответе нет HTML. Подсветка цитаты — по индексам
   (`anchor.start/end`), остальное рендерится текстовыми узлами.
4. **Только аддитивные изменения.** Новое поле можно добавить в любой момент;
   переименование/удаление/смена типа — версия v2 и синхронная правка фронта.

## 2. Эндпоинты

| Метод | Путь | Ответ | Назначение |
|---|---|---|---|
| POST | `/api/chat` | `text/event-stream` | Вопрос (список реплик) → поток событий ответа |
| GET | `/api/docs` | `{docs: DocMeta[]}` | Список документов базы (§18.1 п.5) |
| GET | `/api/docs/{doc_id}` | `{doc: DocMeta, chunks: Chunk[]}` | Полный текст документа для просмотра |
| GET | `/api/health` | `{ok, mode, docs, schema_version}` | Проверка живости, режим (mock/live) |

`/api/docs/{doc_id}` может отдавать текст чанками (`Chunk[]`) — фронт сам
склеивает их в тело документа и подсвечивает нужный чанк. Это дешевле, чем
отдавать 500 КБ текста в списке.

### POST /api/chat

Запрос:

```json
{
  "messages": [
    {"role": "user", "content": "Какая арендная плата по договору № А-08/2024?"},
    {"role": "assistant", "content": "Арендная плата составляет 450 000 рублей в месяц (п. 3.1)."},
    {"role": "user", "content": "А в какой срок её вносят?"}
  ],
  "session_id": "s-lz3k9f-a1b2c3"
}
```

- `messages` — вся история сессии, последняя реплика всегда `user`.
  Бэкенд собирает из неё ячейку `Пользователь: … / Ассистент: …` и отдаёт
  в `guard.parse_dialog` — то есть диалог обрабатывается тем же парсером,
  что на платформе.
- `session_id` — для лимитов частоты и логов без текстов вопросов (§5.3).

Ответ — поток `text/event-stream`, кодировка UTF-8. Кадр:

```
event: delta
data: {"text":"Арендная плата составляет "}

```

## 3. События SSE

| Событие | Когда | Payload |
|---|---|---|
| `meta` | сразу после старта | `{request_id, status, confidence}` — статус известен до текста, карточка красится сразу |
| `source` | по мере готовности выдачи | `Source` (см. §4) — чипы источников появляются до конца ответа |
| `delta` | стриминг текста Reason | `{text}` — приращение, склеивается конкатенацией |
| `trace` | после верификации | `Trace` целиком (см. §5) |
| `done` | последнее событие | `Answer` целиком (§6), авторитетная версия |
| `error` | фатальная ошибка | `{code, message}` — UI показывает карточку «сбой связи», не статус ответа |
| `ping` | каждые 15 с тишины | `{}` — keep-alive, фронт игнорирует |

Правила потока:

- `done` обязателен при успехе; без него фронт считает поток оборванным.
- `status` в `meta` может отличаться от финального `done.status` (например,
  fallback после verify) — финальным считается `done`.
- Порядок `source`/`delta` не гарантирован; склейка только по типам событий.
- Обрыв соединения на клиенте — `AbortController` на фронте, бэкенд обязан
  прекратить работу по завершении запроса.

## 4. Объект `Source`

```json
{
  "id": "s1",
  "doc_id": "документы_компании__Договор_аренды_А-08-2024_Северный_Склад",
  "short_name": "Договор аренды № А-08/2024 с ООО «Северный Склад»",
  "doc_type": "company",
  "kind": "contract",
  "path": "п. 3.1",
  "crumbs": ["Договор аренды № А-08/2024 с ООО «Северный Склад»", "п. 3.1"],
  "quote": "Арендная плата составляет 450 000 (четыреста пятьдесят тысяч) рублей в месяц, включая НДС.",
  "anchor": {
    "chunk_id": "документы_компании__Договор_аренды_А-08-2024_Северный_Склад_c031",
    "start": 6,
    "end": 104
  },
  "doc_date": "2024-08-01",
  "valid_from": null,
  "valid_to": null,
  "edition": null,
  "applies_from": null,
  "status": null,
  "score": 0.94
}
```

| Поле | Тип | Обязательность | Источник в ядре |
|---|---|---|---|
| `id` | string | да | бэкенд нумерует `s1…sN` |
| `doc_id` | string | да | `chunk.doc_id` |
| `short_name` | string | да | `index/docs.json` |
| `doc_type` | `law` \| `company` | да | `chunk.doc_type` |
| `kind` | string | да | `docs.json`: contract / supplement / letter / regulation / memo / law |
| `path` | string | да | `chunk.path` («п. 3.1», «ч. 1, абз. 3», «абз. 8») |
| `crumbs` | string[] | да | `[short_name] + path.split(", ")` — бэкенд отдаёт готовый массив |
| `quote` | string | да | дословный фрагмент чанка (тот, что попал в промпт) |
| `anchor.chunk_id` | string | да | `chunk.chunk_id` |
| `anchor.start` | int | да | смещение начала `quote` внутри `chunk.text` |
| `anchor.end` | int | да | смещение конца, эксклюзивно |
| `doc_date` | ISO date \| null | да | документы компании |
| `valid_from` / `valid_to` | ISO date \| null | да | для документов компании и редакций |
| `edition` | ISO date \| null | да | Регламент: дата редакции |
| `applies_from` | ISO date \| null | да | ДС: дата применения |
| `status` | `active` \| `revoked` \| null | да | редакции Регламента |
| `score` | 0..1 | да | итоговый скор (после реранка, иначе RRF) |

`anchor.start = anchor.end = 0` — легальное значение «подсветить нечего»
(документ открывается целиком). Фронт в этом случае подсвечивает чанк целиком.

## 5. Объект `Trace`

```json
{
  "request_type": "edition",
  "request_type_label": "Вопрос о редакции на дату события",
  "standalone_query": "Какая редакция Регламента действовала 15.06.2024",
  "retrieved": [
    {"doc_id": "…ред_2023…", "short_name": "Регламент (ред. от 10.01.2023, утратил силу)", "path": "п. 2.4", "score": 0.91, "channel": "exact-ref+bm25"}
  ],
  "subquestions": [
    {"id": "q1", "text": "Какая редакция действовала 15.06.2024?", "status": "supported", "source_ids": ["s1"], "reason": "valid_to ред. 2023 = 01.03.2025 > 15.06.2024"},
    {"id": "q2", "text": "Какой порог одобрения был на эту дату?", "status": "supported", "source_ids": ["s1"], "reason": "10 000 000 ₽ в п. 2.4 редакции 2023"}
  ],
  "confidence": {
    "value": 0.9,
    "zone": "full",
    "threshold_high": 0.72,
    "threshold_low": 0.35,
    "reasons": [
      "temporal 0.30: дата события попадает в окно ред. 2023",
      "достаточность 0.25: оба подвопроса поддержаны",
      "верификация 0.30: числа из evidence",
      "контекст 0.15: конфликт редакций разрешён кодом"
    ]
  },
  "edition": {
    "applied": "Регламент, ред. от 10.01.2023",
    "event_date": "2024-06-15",
    "note": "На 15.06.2024 действовала редакция от 10.01.2023; редакция от 01.03.2025 к событию не применяется",
    "conflicted": true
  },
  "citations": {"checked": 3, "ok": 3, "failures": []},
  "gates": [
    {"name": "T1: инъекции в документах", "passed": true, "detail": "compromised-строк нет"},
    {"name": "verify-lite: числа из evidence", "passed": true, "detail": "10 000 000, 15 000 000"}
  ],
  "degraded": [],
  "timings": {"total_ms": 2250, "retrieval_ms": 260, "llm_ms": 1990},
  "model": "gpt-4o-mini"
}
```

| Поле | Источник | Зачем на экране |
|---|---|---|
| `request_type` | `guard.parse_dialog` + эвристики | «тип запроса» первой строкой trace |
| `request_type_label` | бэкенд (русская подпись) | фронт не держит словарь типов |
| `standalone_query` | `guard.standalone_query` | эксперт видит, что реально искали |
| `retrieved[]` | `retrieval.search` (до expand) | «найденные положения» с каналами bm25/exact-ref/dense/rerank |
| `subquestions[]` | `reason`/`pipeline` (evidence-mapping) | статусы подвопросов: supported / partial / unsupported / not_established |
| `confidence.value` | `decide` | число и полоса |
| `confidence.zone` | `decide` | зона = один из 4 статусов |
| `confidence.threshold_high/low` | `decide` (калибровка Ф4) | пороги на шкале |
| `confidence.reasons[]` | `decide` (вклад фич) | «почему такая уверенность» |
| `edition.applied` | `temporal.reason_notes` | применённая редакция (D1) |
| `edition.event_date` | `temporal.event_date` | метка на таймлайне |
| `edition.note` | `temporal` | пояснение конфликта |
| `edition.conflicted` | `temporal` | бейдж «конфликт разрешён кодом» |
| `citations.checked/ok/failures` | `verify` | результат проверки цитат |
| `gates[]` | `guard`/`verify`/`decide` | пройденные/проваленные проверки |
| `plan[]` *(v1.1, опц.)* | `reason`/`pipeline` | шаги процедуры: `{title, detail, source_ids[]}` — рендерится нумерованным планом в карточке ответа |
| `clarifying[]` *(v1.1, опц.)* | `guard`/`reason` | уточняющие вопросы пользователю — чипы в карточке, клик отправляет вопрос в чат |
| `degraded[]` | `config` (режим деградации) | честно показываем, что канал отключён |
| `timings` | `pipeline` | скорость, «2.3 с» в карточке |
| `model` | `config.LLM_MODEL` | какая модель отвечала |

### `subquestions[].status`

| Значение | Смысл | Влияние на статус ответа |
|---|---|---|
| `supported` | подвопрос закрыт фрагментом | ≥1 supported при неполном покрытии → `partial` (не отказ, §14.3) |
| `partial` | фрагмент есть, но покрывает часть | то же |
| `unsupported` | фрагментов нет | все unsupported + нет evidence → `refusal` |
| `not_established` | вопрос не разложен / нет предмета | вместе с провалом guard → `question_error` |

## 6. Объект `Answer` (событие `done`)

```json
{
  "id": "r-7f3a",
  "answer": "…одна строка, ≤ 10 000 символов…",
  "status": "full",
  "confidence": 0.93,
  "sources": [ …Source… ],
  "trace": { …Trace… }
}
```

### Статусы (`status`)

| `status` | Подпись в UI | Когда ставит ядро |
|---|---|---|
| `full` | Полный ответ | зона `full` в `decide` (conf ≥ T_high) |
| `partial` | Частичный ответ | зона `partial` (есть supported, но покрытие неполное) |
| `refusal` | Обоснованный отказ | `grounded_refusal` / зона `refusal` |
| `question_error` | Ошибка в вопросе | `guard` не выделил вопрос: пустая реплика, нет предмета, аномалия диалога |

Транспортные сбои (500, таймаут, обрыв потока) **не** являются статусом
ответа: это событие `error` и отдельная карточка «сбой связи» с повтором.

## 7. Ограничения и ошибки

| Что | Значение | Где зафиксировано |
|---|---|---|
| Длина вопроса | 4000 символов, остаток обрезается | `config.MAX_INPUT_CHARS`, фронт `LIMITS.question_chars` |
| Длина ответа | ≤ 10 000, одна строка, без разметки | `pipeline._finalize` |
| Реплик истории | последние 10 пар | `LIMITS.history_turns` (фронт) |
| Запросов на сессию | 20 | `LIMITS.session_questions` (фронт), бэкенд дублирует лимитом частоты |
| Таймаут ответа | 60 с, затем `error{code:"timeout"}` | `webapp.py` |

Коды `error`:

| `code` | Смысл | Поведение UI |
|---|---|---|
| `network` | нет связи с сервером | карточка «сбой связи», кнопка «Повторить» |
| `timeout` | ядро не уложилось в таймаут | то же |
| `rate_limited` | превышен лимит запросов | то же + подсказка про новый диалог |
| `internal` | необработанное исключение | то же, текст общий (без трейса) |

## 8. Безопасность рендера (§18.2)

- `answer`, `quote`, `short_name`, `path`, `note` — всегда текстовые узлы
  (`textContent` / React children). `innerHTML` и `dangerouslySetInnerHTML`
  в коде фронта отсутствуют — проверяется код-ревью и `grep` в CI.
- Подсветка — только через `anchor.start/end`: строка режется на три части,
  средняя оборачивается в `<mark>`. Разметка из данных не исполняется.
- Ответ приходит без markdown (`_finalize` вычищает `*_#\``), поэтому
  markdown-рендерер не нужен и не подключается.
- CORS: только origin интерфейса; `credentials` не используются.
- Секреты — только `.env` на бэкенде; фронт ключей не видит.

## 9. Мок-режим (Фаза 2–4)

- mock (по умолчанию) — `web/src/mock/engine.js` отдаёт те же
  события с теми же полями: 6 демо-ответов (4 статуса, конфликт
  редакций, план действий по процедуре) + честный отказ по шаблону §4.2
  для остальных вопросов.
- `VITE_API_MODE=sse` — живой `webapp.py`. Переключение без правок компонентов.
- Демо-данные документов сгенерированы из индекса скриптом
  `scripts/gen_web_mock.py` (`web/src/mock/kb.json`, 21 документ, 768 чанков).

## 10. Что нужно подтвердить у Ильи

1. **Поле `answer`** — плоская строка (как в сабмите) или список абзацев?
   Сейчас контракт: одна строка ≤ 10 000 (совпадает с `_finalize`).
2. **`subquestions`** — заполнять из evidence-mapping `reason.py` для всех
   вопросов или только для составных? Фронт корректно рендерит пустой массив.
3. **`request_type`** — фиксируем словарь значений:
   `direct | dialog | edition | false_premise | not_established | unclear | procedure`.
   `procedure` — вопрос-процедура, ядро собирает план действий (v1.1).
   Если ядро различает больше (например, `injection`), добавляем аддитивно.
4. **`confidence.reasons`** — строки с вкладом фичи (`фича вес: причина`) или
   структурный `[{feature, weight, reason}]`? Сейчас контракт — строки
   (проще для UI, не ломает вёрстку при длинных формулировках).
5. **`retrieved`** — отдавать до или после `expand`? Предложение: топ-8 после
   реранка/расширения, с пометкой канала.
6. **`question_error`** — ставит ли ядро статус при пустой реплике само, или
   фронт блокирует отправку пустого вопроса (сейчас блокирует).
7. **`anchor`** — готов ли бэкенд считать `start/end` по `quote` в `chunk.text`
   (одна функция на стороне ядра), или отдавать только `chunk_id`, а смещения
   считать фронту? Предложение: считает бэкенд — фронт не знает про
   нормализацию текста чанков.
