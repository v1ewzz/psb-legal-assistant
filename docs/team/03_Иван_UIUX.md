# Иван · UI/UX-дизайнер

Основной документ: `../psb_legal_assistant_build_spec.md`. Общая матрица: `00_Обзор_команды.md`.

## Миссия одной строкой

Дизайн доверия: эксперт за 30 секунд должен **увидеть**, почему этому ответу можно верить (достоверность 25% + допфункции 15%) — и презентация, которая это продаёт.

## Твоя зона в спецификации

| Раздел | Твоя задача |
|---|---|
| **§18.1 Чат и статусы** | Дизайн карточки ответа под 4 статуса (полный / частичный / отказ / ошибка в вопросе): иконка + цвет + подпись бейджа, различимо без чтения текста |
| **§18.1 Источники** | UX чипов-ссылок в тексте ответа → модалка/панель просмотра источника: хлебные крошки (ст. → ч. → абз.), подсветка фрагмента, дата и редакция, valid_from для документов компании |
| **§18.1 Trace «Как принято решение»** | Макет панели: тип запроса → найденные положения → статусы подвопросов → confidence с причинами → применённая редакция → статус проверки цитат. Это главный продающий экран — он должен читаться сверху вниз как логика |
| **§18.1 Таймлайн редакций** | Шкала времени: Регламент 2023 → 01.03.2025 → 2025; ДС №1 с 01.10.2024; К-12 с 21.04.2025. Визуальный якорь дифференциатора D1 — визуально простая и запоминающаяся шкала |
| **Дизайн-система** | Токены: палитра, типографика, отступы, состояния (ховер/лоадер/ошибка/стриминг). Отдаёшь Вове как токены/файл стилей, не как «примерно так» |
| **§18.3 PDF-презентация** | Слайд 1 — порядок проверки + ссылка на репозиторий + ссылка на развёрнутый интерфейс (жюри смотрит его первым!); далее: проблема/пользователь, архитектура, сценарии, примеры ответов **и отказов**, ограничения, развитие |
| **§18.4 Демо-пакет** | Side-by-side визуалы: бейзлайн vs наш на 5 ловушках (инъекция «90 дней», редакции 2024, «пособие по БиР», «плата 500 000», отзыв согласия ПДн) |
| Фактчекинг-UX | Помочь Никите с читабельностью README (структура «где какая логика») |

## Артефакты, за которые отвечаешь

- `design/tokens.json` + стили (палитра, типографика) — источник правды для Вовы
- Макеты: чат, карточка ответа (4 состояния), панель источников, trace-панель, таймлайн, экран просмотра документа
- PDF-презентация (контент — Никита, дизайн — ты)
- Демо-пакет side-by-side (5 картинок-сравнений)

## Твои фазы (стартуй с Фазы 2!)

- **С Фазы 2**: токены + макеты карточки ответа и trace-панели (черновики — Вова верстает по ним скелет сразу).
- **Фазы 3–4**: итерации по живому UI (скриншоты Вовы), дизайн таймлайна и демо-пакета.
- **Фаза 5**: финальная полировка UI, приемка основного сценария.
- **Фаза 6**: презентация PDF (слайд 1 — порядок проверки!), демо-пакет, скриншоты в README.

## Обмен с командой

**Ты отдаёшь**: токены и макеты (Вове — в код), контент презентации в дизайн (от Никиты), side-by-side картинки (в демо-пакет и презентацию).
**Тебе нужно**: от Никиты — фактура: 5 ситуаций кейса → механизм → демо-вопрос, golden-ответы; от Вовы — скриншоты и правдоподобие макетов реальным данным; от Ильи — список полей trace, чтобы панель показывала реальные статусы, а не абстракцию.

## Личный DoD

- [ ] Токены переданы Вове до его Фазы 3 (не наоборот)
- [ ] 4 статуса ответа различимы на скриншоте за 1 секунду
- [ ] Trace-панель проходит «тест объяснения»: человек без знания проекта по одному экрану объясняет, как родился ответ
- [ ] Таймлайн показывает 3 реальные цепочки редакций без каши
- [ ] Слайд 1 презентации: порядок проверки + обе ссылки (репо + интерфейс) читаются с 2 метров
- [ ] 5 side-by-side сравнений собраны на реальных ответах (не на выдуманных)

## Первые 3 задачи (сегодня–завтра)

1. Токены (палитра + типографика) и макет главного экрана: чат слева, источники/trace справа, таймлайн снизу — отдаёшь Вове в первый же день.
2. Дизайн 4 бейджей статуса ответа (цветовая семантика: зелёный = полный, жёлтый = частичный, красный = отказ, серый = ошибка в вопросе) + чип источника.
3. Каркас презентации по структуре §18.3 (10–12 слайдов): слайд 1 — «как проверить», слайд 2 — проблема кейса; слоты под скриншоты подписать заранее.
