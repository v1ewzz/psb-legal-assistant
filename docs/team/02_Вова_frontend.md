## Миссия одной строкой

Веб-интерфейс §18 — витрина дифференциаторов (D1–D4): жюри должно **видеть**, почему наш ответу можно верить (15% оценки + демонстрация достоверности 25%).

## Твоя зона в спецификации

| Раздел | Твоя задача |
|---|---|
| **§18.1 п.1 Чат** | 4 визуально различимых статуса ответа: полный / частичный / отказ / ошибка в вопросе; история диалога в сессии (реплики уходят в то же ядро списком) |
| **§18.1 п.2 Панель источников** | Клик по ссылке → документ с подсвеченным фрагментом; хлебные крошки (ст. → ч. → абз.); дата и редакция; для документов компании — doc_date и valid_from |
| **§18.1 п.3 Блок «Как принято решение» (trace)** | Тип запроса, найденные положения, статусы подвопросов, confidence и причины, применённая редакция, результаты проверки цитат — главный экран для экспертов |
| **§18.1 п.4 Таймлайн редакций** | Визуальная шкала (Регламент 2023 → 01.03.2025 → 2025; ДС №1 с 01.10.2024; К-12 с 21.04.2025) — уникальный визуальный якорь |
| §18.1 п.5–6 | Список документов базы с поиском по названию и полным текстом; уточняющие вопросы в чате; план действий по процедуре |
| **§18.2 Реализация** | React/Vite или чистый JS; SSE-стриминг; `textContent`/санитайзер — **никакого `innerHTML` с данными**; подсветка фрагментов по индексам; лимит длины вопроса и числа запросов на сессию |
| §18.3 | package-lock, сборка фронта в Docker-образ, скриншоты для README и презентации |

## Артефакты, за которые отвечаешь

- `web/` — фронт-приложение: чат, панель источников, trace-панель, таймлайн, просмотр документов
- SSE-клиент + контракт потребления `{answer, status, confidence, sources[], trace{}}` (заморозить с Ильёй до старта Фазы 5)
- Безопасность рендера: санитайзер, подсветка по индексам, обработка длинных/битых ответов
- Сборка фронта в Docker (совместно с Юсефом: Dockerfile, compose.yaml)

## Твои фазы (стартуй раньше Фазы 5!)

- **С Фазы 2**: скелет приложения на мок-данных (мок-режим webapp.py от Юсефа работает без LLM — §18.2), роутинг, каркас компонентов. Не жди, пока ядро будет готово.
- **Фазы 3–4** (параллельно): компоненты trace-панели и таймлайна на реальных полях trace от Ильи; интеграция дизайн-токенов Ивана.
- **Фаза 5** (1–1.5 д): полная интеграция с SSE, основной сценарий, полировка.
- **Фаза 6**: деплой через `docker compose up`, скриншоты, проверка на чистой машине.

## Личный DoD

- [ ] Основной сценарий проходит целиком: вопрос → ответ → клик по источнику → подсветка фрагмента (§18 DoD)
- [ ] Все 4 статуса ответа различимы без чтения текста (иконка + цвет + подпись)
- [ ] Trace-панель показывает: тип запроса, редакцию, confidence с причинами, статус проверки цитат
- [ ] Таймлайн редакций виден на вопросах про Регламент и ДС №1
- [ ] В рендере нет `innerHTML` с данными API (проверить код-ревью); вопрос обрезается по лимиту
- [ ] `docker compose up` на чистой машине поднимает чат одной командой
