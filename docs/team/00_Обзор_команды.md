## 0. Стек: Python, Java — нет (решение)

**Бэкенд — только Python.** Java в проект не добавляем. Причины:

1. **Формат сабмита жёсткий**: ZIP с `solution.py` на входе платформы, плоские `.py` + `requirements.txt` (§2.3). Java-артефакты (JDK/JAR) в этот формат не помещаются — сабмит собирается только из Python-кода и индексных артефактов.
2. **Одно ядро — два входа**: `pipeline.py` обязан работать и в `solution.py` (пакетный прогон на платформе), и в веб-бэкенде. Java-бэк = полная переписка ядра = два расходящихся кода (split-brain), вдвое больше багов на дедлайне.
3. **Библиотеки**: faiss-cpu, bm25s, rapidfuzz, httpx — питоновские (§2, §9).
4. **Скиллы Юсефа переносятся 1:1**: Docker, API-контракты, устойчивость, деплой — всё нужно; FastAPI осваивается за полдня (он проще Spring).

Java пригодилась бы только для «ещё одного бэка» — а у нас бэк один и он уже занят ядром RAG.

## 4. Дисциплина и ритм

- **Сабмиты (5/день)**: только по правилу §17.3 — «сабмит только после зелёного eval». Порядок: №1 формат → №2 happy path → №3 temporal+guard → №4 калибровка → №5 freeze. Право «нажать кнопку» — у Ильи, после чеклиста §22.2.
- **Стоп-лист §22.1 знает каждый**: temporal, T1-детектор, код-ссылки, «нет голого отказа», периодическая запись, utf-8-sig, обрезка 10 000. При нехватке времени режем по порядку §19.8 (реранк → dense → LLM-verify → синтетика → часть UI-функций).
- **Ежедневно**: 15-минутный синк (что сделано / что блокирует / кто ждёт кого). Все интерфейсы из §3 проверяются в конце дня — не копить стыковку на последний день.
- **Ключевой риск — Илья (ядро)**: максимальная разгрузка. Никита забирает датасеты и фактчекинг, Юсеф — каркас solution.py и клиент, веб целиком у Вовы/Ивана/Юсефа. Пары на случай форс-мажора: retrieval+guard — Илья/Юсеф; датасеты — Никита/Иван; фронт — Вова/Иван.
- **Секреты**: ключи только в `.env`, `.env.example` без значений (§18.2); в логах на платформе не логировать тексты вопросов (§5.3).
