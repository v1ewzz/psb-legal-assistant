# Frontend · веб-интерфейс юридического ассистента (§18)

React 19 + Vite. Четыре зоны экрана: **чат** (слева), **источники / trace**
(справа, вкладки), **таймлайн редакций** (снизу), **документы базы** (модалка).
Тёмная тема на CSS-переменных из `src/styles/tokens.css` (черновик до токенов
Ивана — замена одним файлом, JSX не меняется).

## Запуск

```bash
cd web
npm install          # ставит React/Vite по package-lock.json
npm run dev          # http://127.0.0.1:5173, мок-режим без LLM и без Python
npm run build        # сборка в web/dist
```

Проверено на Node 24 / npm 11. Если `npm run dev` биндится только на IPv6
(`::1`), добавьте `-- --host 127.0.0.1`.

## Два режима

| Режим | Включение | Что работает |
|---|---|---|
| **mock** (по умолчанию) | `VITE_API_MODE=mock` | всё, кроме живого ядра: 5 демо-ответов, документы и чанки из `src/mock/kb.json`, честный отказ по шаблону §4.2 на прочие вопросы |
| **sse** | `VITE_API_MODE=sse` | живой `webapp.py`: `POST /api/chat` (SSE), `GET /api/docs`, `GET /api/docs/{id}` |

```bash
# второй терминал, из корня репозитория:
uvicorn webapp:app --port 8000
# фронт на живой бэкенд:
VITE_API_MODE=sse npm run dev
# прокси /api → 127.0.0.1:8000 уже настроен в vite.config.js
```

Контракт зафиксирован в `../docs/api_contract.md`; типы и нормализация —
`src/api/contract.js`. Мок отдаёт **те же** события SSE (`meta → source* →
delta* → trace → done`), поэтому переход на живое ядро не меняет компоненты.

## Основной сценарий (DoD §18)

1. Вопрос (подсказка под полем ввода или свой текст).
2. Карточка ответа: бейдж статуса (иконка + цвет + подпись), confidence,
   текст, чипы источников.
3. Клик по чипу или карточке источника → модалка документа: хлебные крошки
   (документ → п. 3.1), подсвеченный фрагмент, дата и редакция.
4. Вкладка «Как принято решение»: тип запроса, найденные положения, статусы
   подвопросов, confidence с причинами, применённая редакция, проверка цитат,
   гейты, тайминги.
5. Таймлайн: три цепочки (Регламент 2023 → 01.03.2025, ДС № 1 с 01.10.2024,
   письмо К-12 с 21.04.2025); на вопросе о редакции появляется метка даты
   события.

Демо-подсказки покрывают все четыре статуса:

| Подсказка | Статус | Что показывает |
|---|---|---|
| Полный ответ: арендная плата | `full` | две цитаты, 3/3 цитат подтверждены |
| Частичный: отзыв согласия ПДн | `partial` | 1 из 2 подвопросов поддержан (не голый отказ) |
| Отказ: пособие по БиР | `refusal` | отказ называет тему, «по памяти не отвечаю» |
| Ошибка в вопросе | `question_error` | нет предмета запроса — retrieval не запускался |
| Таймлайн: редакция Регламента | `full` | конфликт редакций, метка 15.06.2024 на шкале |

## Безопасность рендера (§18.2)

- `innerHTML` / `dangerouslySetInnerHTML` не используются вообще: весь текст
  (ответ, цитата, название документа, путь) идёт текстовыми узлами.
- Подсветка — по индексам `anchor.start/end` внутри текста чанка; строка
  режется на три части, средняя оборачивается в `<mark>`.
- Длинный ответ: карточка не ломает раскладку (`white-space: pre-wrap`,
  `word-break`), пустой ответ рендерится явной подписью.
- Вопрос обрезается до 4000 символов на клиенте (лимит ядра) с уведомлением.
- Лимит 20 вопросов на сессию, лимит 10 пар реплик истории.

## Docker (§18.3)

```bash
cd web
docker build -t psb-web .
docker run --rm -p 8080:80 psb-web     # http://127.0.0.1:8080
```

Статика собирается в `node:20-alpine` и раздаётся `nginx`. Для compose —
сервис `web` (подключение за Юсефом, бэкенд `web:8000`):

```yaml
  web:
    build: ./web
    ports:
      - "8080:80"
    depends_on:
      - api
```
