# ПСБ · Юридический ассистент

RAG-ассистент по закрытой базе нормативных документов (13 законов + 8 документов компании ООО «Меридиан», 21 TXT-файл) для Hack&Change 2026.

Ассистент:
1. находит положения, в том числе из нескольких источников;
2. отвечает со ссылками на конкретные пункты/части;
3. обоснованно отказывается, если данных нет, и **не** отказывается, если ответ в базе есть;
4. различает: нехватку данных, ошибку в постановке вопроса, дату/редакцию, противоправные просьбы, атаки на роль;
5. имеет веб-чат с просмотром документов и подтверждающих фрагментов.

## Архитектура

Конвейер одного вопроса (`pipeline.answer_one` — общее ядро для batch и web):

```
parse_dialog (guard)   одиночный вопрос / диалог: последняя реплика + история
Analyze-lite (LLM)     standalone-rewrite диалога, JSON + repair; сбой → эвристика
Retrieve (retrieval)   мульти-запросы → BM25 → RRF → exact-ref boost → реранк (API)
                       → expand (сосед, full-doc); temporal-фильтры редакций
Temporal (temporal)    дата события кодом; заметки «какая редакция действует» (D1)
Reason (LLM)           ответ по фрагментам в стиле эталона §4.2
Verify-lite (pipeline) числа из ответа обязаны найтись в evidence; ловушка T1;
                       1 ретрай → экстрактивный fallback (никогда не пусто)
```

Дифференциаторы (стоп-лист, не вырезать):
- **D1** Temporal-слой: заметки строит код (`temporal.reason_notes`), blanket-правил про редакции в промпте НЕТ (см. риск-журнал №1)
- **D2** Детектор инъекций в документах (T1) — compromised-строки не попадают в индекс вовсе
- **D3** Ссылки из метаданных чанков + verify-lite по evidence
- **D4** Нет голого отказа: фрагменты найдены → экстрактивный fallback, не «не могу»

## Риск-журнал (уроки сабмитов)

| # | Урок | Где учтено |
|---|---|---|
| 1 | Правило промпта «если несколько редакций — указывай обе» дало регресс 27.4→20.8: оговорки лезли во все ответы про Регламент, а эталон так не отвечает (§4.3) | Редакционная логика — только в коде (`temporal`), заметка появляется лишь при дате события в вопросе |
| 2 | Чанки «блоками» ~900 симв. рвали пункты: модель видела «3.1. Арендная плата составляет…» без суммы | `ingest.py` v2: чанк = пункт, `path` = «п. 3.1» |
| 3 | Шапочные абзацы договоров (номер договора в каждой строке) забивали выдачу у диалоговых вопросов | Шапка — один чанк «шапка», вне абзацев |
| 4 | Слабый стемминг: «одобрению»≠«одобрение», «директором»≠«директор» — промахи BM25 | `tokenize_ru`: расширенные суффиксы, единый для индекса и запроса |
| 5 | Диалоговые ячейки целиком в BM25 и промпт → ответ не на последний вопрос | `guard.parse_dialog` + эвристические запросы + Analyze-lite |
| 6 | verify-lite падал на «10.01» из дат редакций в ответе | Заметки temporal входят в evidence_src для verify |
| 7 | **Сабмит v2 = 23.688 (регресс от 27.4)**: правило «назови X, а не Y (из вопроса)» + verify «каждое число — из evidence» противоречили друг другу — легитимные числа ИЗ ВОПРОСА («500 000», «12 млн») топили ответ в фолбэк | verify принимает числа из evidence ∪ вопроса (точные ключи: токены + компактные группы + развёртки «N млн»); правило 4 различает утверждённую норму и исходные данные |
| 8 | Analyze-lite (LLM-rewrite диалогов) — лишний вызов и риск кривого rewrite на критическом пути retrieval/temporal | Убран: эвристические запросы дают recall@8=100%; история диалога по-прежнему идёт в Reason |
| 9 | «500 000» проходило verify как подстрока «450000» (потокенная проверка) | Ключи чисел сравниваются точно (множество), не подстрокой |
| 10 | Слабый реранкер/кламп прокси мог выкинуть BM25-топ из выдачи | BM25-топ-2 всегда остаётся в финальной восьмёрке |

## Где какая логика

| Модуль | Ответственность |
|---|---|
| `solution.py` | Пакетный вход платформы: чтение `questions.csv` (utf-8-sig), дедуп id, ThreadPoolExecutor, периодическая запись `submission.csv`, дедлайн 16 мин, `os._exit` |
| `pipeline.py` | `answer_one(question, ctx, deadline)` — общее ядро для batch и web |
| `config.py` | Резолв переменных окружения, режим деградации, константы |
| `llm_client.py` | `chat() / embed() / rerank() / probe_all()`, ретраи, тайм-ауты, repair JSON |
| `ingest.py` | Парсеры 21 файла, чанкинг, edges, `--build-index` (артефакты 7 шт.) |
| `retrieval.py` | Каналы exact-ref / BM25 / dense → RRF → rerank → расширение (parent, refs, edges) |
| `temporal.py` | Окна редакций, версии пунктов, статусы `edition_*`, даты/сроки считает код |
| `guard.py` | Парсер диалога, детектор compromised-чанков (T1), вызов Analyze |
| `reason.py` | Reason-вызов, evidence-mapping по подвопросам |
| `verify.py` | Детерминированные проверки (cNN, цитаты, числа/даты) + LLM-verify в серой зоне |
| `decide.py` | Confidence-фичи, пороги T_high/T_low, зоны ответа |
| `render.py` | Подстановка ссылок из метаданных, шаблоны эталонного стиля, длина ≤10 000, одна строка |
| `webapp.py` | FastAPI + SSE, тот же `pipeline.answer_one` |

## Запуск

```
# локальная разработка
py -m venv .venv && .venv\Scripts\python -m pip install -r requirements.txt
cp .env.example .env   # заполнить ключи (ключи только в .env, в репо не класть)

# сборка индекса v2 (чанки по пунктам) из базы знаний
.venv\Scripts\python ingest.py --build-index --kb data/kb.zip

# пакетный режим (как на платформе): demo questions.csv → submission.csv
set DATA_DIR=data
.venv\Scripts\python solution.py

# локальный eval без LLM (ключ недоступен, U9):
.venv\Scripts\python eval/runner.py recall            # retrieval recall@8 по demo-18
.venv\Scripts\python eval/runner.py facts             # факт-чек submission.csv против эталона

# веб-чат (Фаза 5)
uvicorn webapp:app

# фронт (§18): мок-режим без LLM, подробности в web/README.md
cd web && npm install && npm run dev

# сборка сабмит-ZIP (плоские модули + артефакты в корне, §2.3)
.venv\Scripts\python scripts/make_submit.py
```

## Переменные окружения

См. `.env.example`. Ключевые: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `EMB_MODEL`, `RERANKER_MODEL`, `DATA_DIR`, `MAX_WORKERS`.

## Известные ограничения

- Скрытая база поставляется платформой в `data/kb.zip` — в репозиторий не входит.
- Ключи API приходят через окружение; в ZIP-сабмит и в репозиторий не кладутся.
- «Сегодня» в temporal-логике = дата выгрузки базы (10.10.2026), не системное время.
- Dense-канала нет (BM25 + exact-ref + реранк); при недоступности реранка — деградация к RRF-порядку (§8.3), recall@8 на демо-18 в этом режиме 100%.
