# ПСБ · Юридический ассистент (ядро v3)

RAG-ассистент по закрытой базе нормативных документов (13 федеральных законов + 8 внутренних
документов ООО «Меридиан», 21 файл, 321 чанк) для Hack&Change 2026.

**Финальный балл платформы — 33.302** (сабмит v3, 16.11.2026). Прошлый лучший — 27.615
(sabmit v2.1): **+21% к лучшему результату** при том же лимите 16 минут на пакет.

## Что внутри (v3.0)

Ядро — рерайт v2-конвейера: меньше модулей, гибридный поиск и постатейная верификация.

```
dialog        реплики → последняя реплика + история; кламп с сохранением хвоста;
              зависимые реплики («а какая там неустойка?») → rewrite через LLM или контекст
retrieve      BM25(текст) + BM25(doc2query) + dense(bge-m3) → RRF → бусты метаданных
              (точные ссылки «А-08/2024», «ст. 152», редакции) → реранкер → расширения
              (перекрёстные ссылки, связанные документы/редакции, соседние пункты)
legalctx      доверенные заметки для модели КОДОМ: статус/редакция каждого документа,
              будущие изменения, конфликты чисел между документами
generate      один LLM-вызов, промпт 9 правил, фрагменты <fragment> с атрибутами
verify        постатейная проверка КАЖДОГО предложения: числа (+млн/тыс, словесные),
              даты, ссылки (пункт существует; статья принадлежит именно тому акту),
              «календарные vs рабочие», опора на утратившую силу редакцию без оговорки;
              лексическая поддержка → слабые утверждения проверяет LLM-судья
post          ≤1 регенерация с фидбеком → удаление неподтверждённых предложений →
              экстрактивный fallback. Ответ никогда не пуст и не выдуман
runtime       пул потоков, дедлайн 16 мин, уровни деградации по бюджету времени,
              кэш ответов (LRU + диск), submission.csv пишется сразу и атомарно
```

Дифференциаторы (все включены по умолчанию, отключаются env-флагами):

- **D1 Temporal-слой**: редакции и статусы считает код по метаданным индекса
  (`legalctx.build_notes`), в промпте нет blanket-правил про редакции.
- **D2 Инъекции в документах**: compromised-строки отсекаются при построении индекса
  (`ingest.is_compromised`) — в промпт не попадают вовсе.
- **D3 Проверяемые ссылки**: каждый «п. N.M»/реквизит/статья в ответе сверяется
  с фрагментами (`verify`); фантомных пунктов не бывает.
- **D4 Нет голого отказа**: фрагменты найдены → экстрактивный fallback с цитатами;
  регенерация после провала verify; отказ только когда данных действительно нет.

## История баллов платформы

| Сабмит | Состав | Балл |
|---|---|---|
| N1 | BM25-блоки + один LLM-вызов + verify-lite | 27.4 |
| правила 4–9 | + правила промпта | 20.8 |
| v2 | чанки-пункты, диалоги, реранк, temporal | 23.688 |
| v2.1 | фикс конфликта verify↔правила | 27.615 |
| v2.2 | гейты/инъекции/шапки (промпт 11 правил) | 25.032 |
| head | все фиксы, но урезанный промпт | 20.038 |
| **v3** | **гибридный поиск + постатейная верификация + судья** | **33.302** |

Урок v2.x: расширение промпта правилами стоило баллов (каждое правило ломало соседние
ответы). В v3 промпт на 9 правилах стабилен, а качество растёт от **кодовой** верификации.

## Запуск

```
py -m venv .venv && .venv\Scripts\python -m pip install -r requirements.txt
cp .env.example .env        # ключи только в .env (LLM_BASE_URL, LLM_API_KEY, модели)

# пакетный режим (как на платформе): data/questions.csv → submission.csv
set DATA_DIR=data
.venv\Scripts\python solution.py

# веб-чат (тот же pipeline.answer_one)
uvicorn webapp:app          # http://127.0.0.1:8000 ; или docker compose up

# офлайн-проверки (без сети и ключей)
.venv\Scripts\python -m pytest tests -q
```

Без ключей в окружении конвейер работает в деградированном режиме: поиск по BM25 +
расширения, ответ — экстрактивный (цитаты из найденных положений). Веб-интерфейс при
этом полностью работоспособен.

## Структура

```
solution.py        точка входа платформы: questions.csv → submission.csv, дедлайн, os._exit
pipeline.py        ядро одного вопроса: dialog → retrieve → legalctx → generate → verify → post
config.py          env-конфиг (модели/ключи только из окружения), константы, клампы
dialog.py          разбор диалоговой ячейки, кламп-хвост, rewrite зависимых реплик
retrieval.py       BM25+doc2q+dense → RRF → метаданные → реранк → расширения; загрузка индекса
legalctx.py        заметки о статусах/редакциях/конфликтах для промпта (код, не промпт)
verify.py          постатейная проверка чисел/дат/ссылок/статуса + LLM-судья слабых утверждений
ingest.py          парсеры TXT/MD/DOCX, чанкинг по пунктам, edges, детектор инъекций, --build-index
runtime_utils.py   кэши (LRU single-flight, диск), бюджет времени, тайминги этапов
textutil.py        нормализация, токенизация/стемминг, числа/даты/пары «число+единица»
webapp.py + web/   FastAPI + SSE: чат, источники с подсветкой, трасса, таймлайн, документы
index/             артефакты индекса (chunks.jsonl.gz, docs.json, manifest.json)
tests/             офлайн-тесты ядра (диалог, verify, legalctx, поиск, контракт CSV)
eval/              судья §1.2 (judge.py), real_eval.py, демо-эталоны, история реплеев
docs/              документация команды, скриншоты, исходник презентации
```

## Переменные окружения

См. `.env.example`: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `EMB_MODEL`,
`RERANKER_MODEL`, `DATA_DIR`, `MAX_WORKERS`; флаги каналов: `HYBRID`, `RERANK`,
`CLAIM_JUDGE`, `REWRITE_FOLLOWUPS`, `CITATION_LINT`, `T5_GATE`, `CACHE`, `AS_OF_DATE`.

## Известные ограничения

- Скрытая база поставляется платформой в `data/kb.zip` — в репозиторий не входит; при
  наличии kb.zip индекс инкрементально синхронизируется с ним (переиспользуются чанки).
- Dense-канал и реранк требуют эмбеддер/реранкер в окружении; без них — RRF-порядок.
- «Сегодня» в temporal-логике = дата выгрузки базы (10.10.2026), не системное время.
- Демо-ответы (`data/demo_output.csv`) получены на ядре v2.1; интерфейс и правила
  конвейера совпадают, но v3 может формулировать иначе.
