# ПСБ · Юридический ассистент

Прототип для Hack&Change 2026: ответы по предоставленному учебному корпусу,
ссылки на положения, работа с диалогами и контроль части ошибок генерации.
Основной пользователь — юрист; руководитель юридического подразделения проверяет
основания вывода. Цель — сократить поиск и упростить проверку, эффект во времени не измерен.

Корпус: **21 TXT-файл — 13 файлов с нормативными выдержками и 8 документов компании**.
Это не 13 разных федеральных законов и не реальные внутренние документы банка.

## Состояние этой ветки

Ветка аналитики `codex/nikita-final-review` основана на более новом `lean-v1`,
коммит `f792b674e27b2e27aed8ee7f92fea379df8cc4c2`.
Изменения касаются данных, офлайн-оценивания, тестов и документов. Ядро, интерфейс,
конфигурация и зависимости не изменены. Эта ветка не объявлена командой финальной версией сдачи.

Результаты от 16 ноября:

- 18 демовопросов и ответов получены из папки организаторов; эталоны уточнены по TXT.
- 12 самостоятельно составленных ловушек имеют исходные цитаты и ошибочные примеры.
- Проверены 52 привязки к строкам оригиналов; происхождение и SHA-256 — в `eval/source_manifest.json`.
- 31 новый тест оценивания прошли на стандартной библиотеке без сети, установки и модели.
- По индексу: 11 статических проверок PASS, 3 FAIL по отсутствующим структурированным датам,
  1 REVIEW по точности путей положений. Это адаптированный чеклист, а не исходная §7.5.
- Полный pytest, retrieval-прогон, приложение, Docker и LLM-проверки не выполнялись:
  готовых зависимостей недостаточно; установки и API-вызовы запрещены пользователем.

Подробности и блокеры: [итог аналитики](docs/nikita_completion_report.md),
[состояние работы](docs/nikita_work_status.md), [отчёты](docs/reports/).

## Одна команда для офлайн-проверки доступной части

Из корня репозитория, при наличии обычного Python 3:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_eval_quality.py -v
```

Без ключей и зависимостей проекта. На Windows PowerShell переменную можно задать
как `$env:PYTHONDONTWRITEBYTECODE='1'`, затем выполнить `python -m unittest ...`.

При наличии исходных материалов локально:

```bash
python3 eval/runner.py validate
python3 eval/runner.py history
python3 eval/runner.py facts --submission path/to/submission.csv
python3 eval/audit_index.py
```

Смысл результатов и форматы: [eval/README.md](eval/README.md).
Успех проверки набора или regex-правил не равен юридической приёмке и баллу LLM-судьи.

## Запуск приложения в подготовленном окружении

Требуется окружение с зависимостями `requirements.txt`. В этой сессии они не устанавливались.
Веб-зависимости в исходном файле пока не все зафиксированы по версиям — задача владельца сборки.

Команда проекта для всех компонентов:

```bash
docker compose up
# http://127.0.0.1:8000
```

Compose собирает образ и устанавливает пакеты во время сборки: команда **не запускалась**
в этой проверке из-за запрета установок. Для уже подготовленного Python-окружения:

```bash
python -m uvicorn webapp:app --host 127.0.0.1 --port 8000
```

Перед запуском настроить окружение. Compose ожидает `.env`, сам uvicorn автоматически
его не загружает. Имена переменных — в `.env.example`; действующие ключи не публикуются.
Без ключа генерации в коде предусмотрен экстрактивный fallback, но его успешная работа
в интерфейсе этой сессией не подтверждена.

Основной сценарий приёмки: задать вопрос → сверить вывод со статьёй/пунктом → открыть
источник → проверить подсветку → проверить статус, дату и честность trace. Отдельно
проверить ложную сумму, отсутствие данных, смешение контрагентов и дату события.

**До сдачи владельцам ядра/UI нужно проверить связку:** `webapp.answer_rich` ожидает,
что ядро заполнит `ctx['collect']`, а выбранный lean-pipeline этого не делает.
Из кода следует риск пустых источников и неполной трассы; фактическое UI-поведение
не проверено. Структурированные даты отсутствуют в lean `docs.json`, хотя даты есть
в текстах. Наличие файлов веб-чата не является подтверждением успешной интеграции.

## Где какая логика

| Файл | Фактическая ответственность выбранного lean |
|---|---|
| `solution.py` | Вход CSV, загрузка контекста, пакетная обработка, запись submission |
| `config.py` | Переменные окружения, ограничения и флаги |
| `ingest.py` | Подготовка корпуса и индекса, исключение инструкций-инъекций |
| `retrieval.py` | BM25, приоритет документов по реквизитам, опциональный sibling-fill |
| `index/` | Готовый lean-индекс: 255 блоков; doc2query подготовлен командой раньше |
| `pipeline.py` | Кламп вопроса, evidence до 6000 символов, фрагмент до 1800, генерация, проверки, fallback |
| `guard.py` | Утилиты разбора диалога; их наличие не доказывает использование внутри lean answer_one |
| `llm_client.py` | Генерация/эмбеддинги/реранк, обработка ошибок; ночью не вызывался |
| `webapp.py`, `web/` | FastAPI/SSE и фронт; интеграция требует отдельной проверки |
| `eval/quality.py` | Чистые офлайн-правила и диагностика, без импорта ядра |
| `eval/runner.py` | Проверка источников, сохранённых ответов и истории без API |
| `eval/audit_index.py` | Статическая сверка индекса с TXT |
| `eval/real_eval.py` | Отдельный живой прогон; ночью не запускался |
| `scripts/make_submit.py` | Сборка ZIP; локальная проверка структуры — в package_check.json |

Не следует приписывать lean готовый RRF, полноценный temporal-слой или автоматически
подтверждённую проверку каждого юридического утверждения по старой архитектурной схеме.

## Данные и окружение

Разрешённые исходники находятся локально в `data/`: `knowledge-base.zip`,
`demo_questions.csv`, `demo_output.csv`, распакованные TXT в `data/originals/`.
Оригиналы не добавлены в Git. Для воспроизведения проверок получить те же файлы по
ссылкам из `eval/source_manifest.json` и сверить SHA-256.

Для платформы: `DATA_DIR` указывает на вопросы и базу; адрес/ключ/модель берутся из
`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` и поддерживаемых алиасов. Другие настройки:
`MAX_WORKERS`, `MAX_TOKENS`, `TOP_K`, `SIBLING_FILL`, `VERIFY_V2`, `CITATION_LINT`,
`CALC_NOTE`, `PREMISE_NOTE`. Перед запуском сверить их актуальные имена с `config.py`.
Порядок выдачи ключа — по регламенту организаторов; свои значения в материалы не включать.

Пакетный запуск `python solution.py` может обращаться к модели и не выполнялся ночью.
Сборка `python scripts/make_submit.py --outdir build/review` сама модель не вызывает.
Проверенный архив — 12 файлов в корне, 214873 байта, без пропущенных локальных импортов;
это не проверка исполнения в окружении платформы и не отправленный сабмит.

## Известные ограничения

- Только предоставленный корпус; исторические и будущие редакции законов не восстанавливаются по памяти.
- Числа из вопроса, разные основания, отрицания и условия требуют смысловой проверки.
- Детерминированные правила не гарантируют отсутствие галлюцинаций.
- Полный список ловушек, исходные девять категорий и чеклист §7.5 из спецификации не найдены.
- API-пробы и новая калибровка не проводились. Числа 0.289/0.738/0.943 из командных
  материалов не подтверждены новым измерением; это разные методики и версии.
- Исправления eval меняют локальную диагностику: её новые значения нельзя сравнивать
  со старым score как рост качества самого ассистента.
- Приёмка/merge и фактическая сдача решения остаются отдельными действиями команды.
