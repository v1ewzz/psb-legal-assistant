## Слайд 1 — «Как проверить решение» (ПЕРВЫЙ!)

- **Порядок проверки** (нумерованные шаги, крупные):
  1. Открыть веб-интерфейс: `<ссылка на развёрнутый UI>` *(крупно, оранжевым)*
  2. Репозиторий: `github.com/v1ewzz/psb-legal-assistant` *(крупно)* — ветка `LeBWa-UI/UX` / main, `docker compose up`
  3. Проверить сценарий: вопрос → ответ с чипами → клик по чипу → подсвеченный фрагмент
  4. Спросить про редакции («аренда А-08 с 01.10.2024»), про инъекцию («90 календарных дней»), про выдуманную цифру («плата 500 000»)
- Модель: DeepSeek V4.1 Flash (по Техническому регламенту) · поиск BM25+/edges — свой, без внешних источников.

## Слайд 2 — Проблема и пользователь
- Юрист банка ищет положения в 21 документе (13 законов + 8 документов «Меридиан») — это часы.
- Глазами пользователя: юрист (найти нормы) + руководитель юрдепартамента (проверить основания выводов).
- Страх: RAG в юрпрактике галлюцинирует — «несуществующий закон» хуже, чем «нет ответа».

## Слайд 3 — Наш ответ: принцип «дизайн доверия»
- Не «умный ответ», а **проверяемый ответ**: каждое утверждение → ссылка → фрагмент.
- Четыре зоны честности: полный / частичный / отказ / ошибка в вопросе.
- Скриншот: макет главного экрана (01).

## Слайд 4 — Архитектура
- Конвейер: `parse_dialog → Analyze → Retrieve → Temporal → Reason → Verify → Decide → Render`
- Одно ядро для batch и web. Поиск: BM25 + расширение (parent/refs/edges), опц. реранк Qwen3.
- Дифференциаторы D1–D4 по стрелкам на схеме.

## Слайд 5 — D1 Temporal: редакции на дате события
- Скриншот таймлайна (04): Регламент 2023→01.03.2025→2025; А-08 + ДС №1 с 01.10.2024; К-12 с 21.04.2025.
- Пример: «аренда А-08 с 01.10.2024» → 510 000, а не 450 000; старая редакция — только как история.

## Слайд 6 — D2/D3: инъекции и проверяемые ссылки
- Инъекция «90 календарных дней» отбрасывается детектором до промпта — не влияет на ответ.
- Ссылки формирует код + верификация: нет выдуманных пунктов, числа сверены 3/3.

## Слайд 7 — D4: четыре зоны ответа
- Скриншот карточек (02): полный / частичный / отказ / ошибка в вопросе.
- Отказ показывает, ЧЕГО не хватило. Не отказываемся, если ответ в базе есть (ограничение 09).

## Слайд 8 — Trace «Как принято решение»
- Скриншот trace-панели (03): запрос → положения → редакция → confidence с причинами → проверка цитат → вердикт.
- Фраза-крючок: «Эксперт видит не ответ — он видит, как ответ родился».

## Слайд 9 — Демо-пакет: бейзлайн vs наш (side-by-side)
- 5 ловушек на реальных ответах: инъекция «90 дней» · редакции 2024 · «пособие по БиР» · «плата 500 000» · отзыв согласия ПДн.
- 2–3 самых выразительных сравнения на слайд, полный комплект — в демо-пакет.

## Слайд 10 — Метрики и скорость
- Оценка LLM-судьи vs бейзлайн (сабмиты №1–3), локальный eval (`eval/runner.py`).
- Время ответа, деградация при тайм-ауте: fallback экстрактивный, никогда не пусто и не выдумка.

## Слайд 11 — Ограничения (честно)
- Только база знаний, внешние источники не используются. Законы — только действующая редакция.
- «Сегодня» = дата выгрузки базы (10.10.2026). Моковые данные в демо, реальные доки банка не входят.

## Слайд 12 — Развитие
- Dense-поиск bge-m3 + реранк Qwen3 → гибрид; уточняющие вопросы перед поиском; план действий по процедуре («согласование договора: шаги 1–5»); интеграция с СЭД банка.
